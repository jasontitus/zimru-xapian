# Memory-safety worklist

## Whole-app target and current status

The owner trusts the operating system and standard runtime. Application code and dependencies that process untrusted content must be memory safe. The application does **not yet meet this target**. A keyword scan, a safe API or a passing test covers only part of that claim. OS-provided WebViews fall within the platform boundary. The Linux AppImage ships its own WebKitGTK, JavaScriptCore and GStreamer libraries. Those copies, app-owned bridges and other dependencies processing archive content remain in scope.

The Apple silicon desktop release at `f7fc9b8` compiled **86 distinct unsafe Rust sites in the app crate** and **17,251 target-side sites across 420 packages**. The earlier release at `541725a` recorded 17,255. The checked html5ever and markup5ever libraries each compiled with zero unsafe-code diagnostics on both host and target. The published crates previously accounted for three and one distinct sites, respectively. In that build, published Tendril accounted for 120 target sites and the string interner for 19. The app now selects checked Tendril storage. These counts cover Rust before linker elimination in one release configuration. Native code and other platform builds require separate evidence. [Current compiler receipt](audit/2026-11-18-macos-checked-html-compiled-unsafe.json) · [Previous receipt](audit/2026-11-18-macos-bonjour-compiled-unsafe.json) · [Collection method](audit/2026-11-18-macos-compiled-unsafe.md)

The earlier Bonjour change reduced the Rust discovery worker from 29 sites to 24. It followed an integer-handle change that removed eleven sites from Nearby transport, which still accounts for eleven. The voice decoder change removed another 100 target-side sites from the old bzip2 libraries. [Handle and voice checkpoint](audit/2026-11-18-macos-handle-ids-compiled-unsafe.json)

## Filesystem boundary update

`fs_ext.rs` now forbids unsafe Rust on Unix. Advisory locks use typed `rustix::fs::flock` operations with a borrowed file, and volume space comes from `rustix::fs::statvfs`. Windows uses standard-library nonblocking file locks, preserving error 33 for contention. The Windows volume lookup still calls the OS through an app-owned unsafe wrapper. Both paths reject embedded NUL characters. macOS exercised lock contention and release, volume queries, and path errors. Windows, Linux, iOS and Android ARM64 were type-checked. Windows and mobile behavior still need execution on those targets.

Exclusive Unix publication in the library, acquisition, Nearby, map and torrent paths uses `rustix::fs::renameat_with` with `RenameFlags::NOREPLACE`. Five Rust modules now forbid unsafe code on Unix, removing the six app-crate sites attributed to publication in the macOS compiler inventory. Descriptor-relative operations retain both directory handles and propagate the filesystem error. On Linux and Android, the existing ambient-path publisher can still hard-link a regular file and unlink the source if the kernel or filesystem rejects exclusive rename with `ENOSYS`, `EINVAL` or `EOPNOTSUPP`. A failed source unlink is reported after the destination has been linked. The typed wrapper still trusts rustix and the operating system.

macOS tests exercised parent replacement, destination collisions and interrupted publication recovery. A Linux virtual machine also ran the actual publication module built for ARM64 Linux, ARM64 Android and 32-bit ARM Android. Those runs exercised the kernel rename, all three fallback errors, refusal to fall back on a cross-device error, and a failed source unlink after the destination was linked. Physical mobile devices and FAT/exFAT volumes were outside this check.

The desktop profile rendezvous and the Unix agent-connector transport forbid unsafe Rust in their app-owned modules. The Apple/BSD rendezvous uses the typed `nix::unistd::getpeereid` wrapper on the connected socket. The app enables the pinned nix package’s `user` feature on those targets, and the OS credential call remains inside that dependency. Linux retains `SO_PEERCRED`. Both rendezvous callers require the returned user ID to match the process's effective user ID, and a failed lookup denies access. The Unix connector retains Tokio's separate peer credential checks. Windows pipe authentication remains a separate platform boundary.

On macOS, accepted and outgoing local sockets authenticated the same account and a nonsocket descriptor failed the rendezvous check. An ARM64 Linux virtual machine exercised both credential APIs from separate processes with matching, different, then matching user IDs. The credential functions compiled in isolation for ARM64 iOS device and simulator targets. The complete app library also passed a separate compile check on each target with the updated dependencies. The application builds the profile rendezvous for desktop. BSD behavior was checked against the pinned wrapper source.

The separate `kiwix-mcp` relay forbids unsafe Rust in its own Unix executable. Linux verifies the connected server's effective user through `rustix::net::sockopt::socket_peercred`, and macOS uses `nix::unistd::getpeereid`. Their operating-system calls and dependency internals remain part of the trust assessment. Windows retains its separate native pipe identity checks. The relay uses a checked SHA-256 implementation for the same 16-character profile socket suffix. The app's other hashing paths remain in the dependency inventory.

An ARM64 Linux virtual machine exercised the release relay through its normal standard-input interface. With the matching test account it sent the profile handshake and returned the test library. With a different server account it closed the socket before sending the handshake. A subsequent matching server worked. A Mac round trip against the signed app also verified that switching the test library into private mode cut off an existing relay and leaving private mode restored access. This test exposed an early readiness report. The connector now publishes readiness after it obtains the socket or named pipe, and ignores late readiness updates from retired listeners.

## Apple Nearby sends and receives

An incoming Apple QUIC read now carries an operation ID and a borrowed immutable dispatch object. Rust checks the size against the caller's buffer and the 256 KiB per-read cap before copying. Cancelling a read retires its ID, so a late or duplicate callback cannot deliver data to another caller. The request registry forbids unsafe Rust. The call into Objective-C++, Apple networking and dispatch2’s native buffer traversal remain in the inventory. [Runtime and performance checks](benchmarks/2026-11-18-apple-nearby-reads.md)

For outgoing data, the Rust send method makes a synchronous copy into immutable dispatch data. Apple’s queue retains the data and the completion block. Readiness and listener acceptance also use owned blocks. Connection and listener leases now carry non-recycled IDs through Rust. The native tables keep objects alive for queued work and reject stale IDs. The native connection state, block2 and dispatch2 implementations, and DNS-SD operations remain in scope. [Handle lifetime and performance checks](benchmarks/2026-11-18-apple-nearby-handles.md) [Send ownership and measurements](benchmarks/2026-11-18-apple-nearby-sends.md)

The Rust Bonjour discovery worker gives the OS a non-recycled operation number. A callback can enqueue an event only while its matching worker and operation are active. Native callback strings and TXT records are still borrowed, and the Rust adapter still owns DNS-SD service references and polls their file descriptors. At `e46993d`, the separate Objective-C++ connection resolver also uses non-recycled operation numbers. It checks the active lookup stage before processing the callback. At `d0c967c` this resolver checks the returned address length before reading IP fields. It uses the same owned address for the on-link check and endpoint creation. At `d7e2124`, the subnet check uses only the address and netmask bytes declared by Darwin. Trailing mask bytes omitted by the OS are zero. [Callback lifetime checks, live discovery and timing](benchmarks/2026-11-18-bonjour-callbacks.md)

A milestone review found six compact IPv4 netmasks on the Mac test host. Five had a total length of seven bytes and one was five bytes. A full IPv4 mask ends at byte eight. The previous subnet test read past those six declared lengths. The reviewed fix passed 2,682 comparisons with live interface records and 19,178 combinations of supplied lengths under sanitizers. Storage beyond the declared records was unspecified. No crash was observed.

The iOS simulator supplied a seven-byte IPv4 /22 mask and two full-sized IPv6 /64 masks. Both builds returned the expected result in all 7,168 measured on-link checks per build. After discarding the first warm-up pair, eight alternating process pairs remained. The median process average was 226.2 µs per check before and 229.0 µs after the fix. The median within-pair change was −1.2%. Each check included obtaining the live interface list. The timings give no consistent speed advantage. [Individual simulator samples](benchmarks/2026-11-18-compact-route-masks.json)

At `3e9e976`, outgoing connections check the peer subnet on the same live interface that the resolver bound. The bridge copies complete IPv4 or IPv6 addresses while their Network.framework endpoint owner is alive. Detailed route receipts use the path’s effective local and remote endpoints. If two interfaces qualify for an incoming receipt, the bridge withholds the interface detail. Link-local IPv6 addresses with conflicting interface scopes are refused.

Independent review reproduced two incorrect results with controlled interface records. The old route predicate accepted one interface’s subnet as evidence for another. An intermediate fix displayed the wrong local IP when an interface had two addresses. The final regression checks cover both cases, interface replacement, and duplicate local addresses in either enumeration order. Twelve native fixture checks passed under AddressSanitizer and UndefinedBehaviorSanitizer on Mac. Independent checks covered 81 combinations of IPv6 scope IDs and 26 live Mac interface address records. The remaining native boundary includes interface enumeration, callback data and the Rust-to-Objective-C++ handoff.

On ARM64 Mac, six alternating pairs of real Bonjour and QUIC library inventory runs each included 64 route lookups per process. One warmup pair was excluded. Median elapsed time was 1.147 s before and 1.174 s after. The median within-pair change was −1.1%, with four of six pairs faster. The test process used more CPU in all six pairs, with a median within-pair increase of 4.4%. The interval includes startup, discovery and cleanup. ## Nearby interface authority

Android's hotspot controller owns the reservation. The Rust socket owner checks its receipt against the kernel interface name and index, link flags, IPv4 address and netmask. It binds a new UDP socket to that device, reads the binding back, binds the local address, checks the live interface again and asks the controller to confirm the lease. A failed check discards the socket. The interface name must be ASCII without an embedded NUL, so lossy conversion of an unrelated kernel name cannot match it.

The app's vendored socket crate also forbids unsafe Rust. It resolves a validated interface name through `nix` and uses checked UTF-8 when returning the retained name. Its IPv4 and IPv6 socket bindings were read back from the kernel on macOS loopback.

The app's Nearby route and library interface modules forbid unsafe Rust. The locked `nix` 0.32.0 wrappers perform the OS name/index lookups, own the `getifaddrs` allocation and read its typed addresses. The existing `socket2` 0.6.5 wrappers perform the socket type read and `SO_BINDTODEVICE` write/read. Those dependencies contain unsafe OS adapters. This path supplies an app-owned descriptor and a validated name to those adapters and receives kernel-provided address records. The Apple QUIC adapter and native Android lease callbacks remain separate boundaries.

Focused tests cover route flags, address family, netmask, interface identity and peer subnet rules. ARMv7 and ARM64 Android executables built for API 24 with the NDK verified the socket type, bound interface name and local address on an isolated, emulated Android API 34 kernel. A substituted interface index failed. This used a private virtual interface and a synthetic controller receipt. App-sandbox permissions, real hotspots, and native lease revocation still require device testing.

## Inventory baseline, 2026-11-17

**Start with the bytes an archive supplies.** Opening a ZIM, decoding a cluster, querying an embedded index, and rendering the resulting article are four separate operations. Switching to the Rust ZIM and Xapian readers would retire the current C++ reader and search code once every consumer switches. The baseline Zimru file mapping and codecs, and the platform rendering engines, need their own decisions.

This is a source inventory of Kiwix Workbench at `921327a76df2167d570d9f88f7a14e5c8009bfd5` (2026-11-17). An open box identifies a boundary to work on. It does not identify a confirmed memory bug. Bare Rust module paths in the tables refer to `src-tauri/src/`. The `native/` and `vendor/` directories sit under `src-tauri/`. Swift and Kotlin plugin filenames refer to [the mobile plugin](../src-tauri/plugins/tauri-plugin-kiwix-mobile).

The macOS transfer power module forbids unsafe Rust. When startup succeeds, a shared worker enters Foundation's scoped activity before the first transfer proceeds and leaves it before the last guard returns. Subsequent first transfers reuse the idle worker. If the worker cannot start or its channel closes during startup, Kiwix logs the failure and continues the transfer without that power assertion. The next transfer after all current guards end can retry. The app no longer moves a native activity token between threads. The Objective-C and block binding crates remain in its runtime dependency graph.

The macOS power-assertion report showed the named sleep assertion while two nested transfer guards were reduced to one, and showed its release after the last guard was dropped on a different thread. Across five local runs of 64 acquire/release pairs, the median run averaged 144 microseconds per pair with the prior implementation and 155 with the shared worker. The measurement covers power transitions, independent of the bytes exchanged by Nearby.

The Rust archive migration removed the handwritten `Send` assertion for `archive::Handle`. Six app-owned thread-safety assertions remain. They cover `RawConnection` and `RawListener` (Send and Sync each) and the Windows connector's `Descriptor` (Send and Sync). Retirement requires checking who can use each handle concurrently, who may destroy it, and whether native callbacks can still run at that point. `fs_ext.rs` now forbids unsafe Rust on Unix and calls typed `rustix` filesystem operations. Windows file locks use the standard library. The two Windows volume queries still have app-owned unsafe calls. The [earlier Rust review](RUST-UNSAFE-REVIEW.md) records the effective-UID and Linux peer-credential changes.

On iOS, the app now gets its container path through Foundation's typed Rust binding, opens the canonical directory with no-follow flags, and retains an owned file handle after checking its type and effective owner. This removes the handwritten Swift path buffer and raw descriptor transfer. The Foundation binding, standard library and filesystem wrappers still call native code. The C bridges for external documents and Nearby remain separate work items. [iOS container verification](audit/2026-11-18-ios-container.md)

The Mac Downloads-folder lookup still reads the real user's account record with `getpwuid_r`. A proposed `nix::unistd::User` replacement also reads an unrelated account class field. Review found its macOS conversion assumes a non-null class pointer. The proposed change was withdrawn. The named-home Foundation APIs returned the app container in a signed test. ## Refresh and closure

Run these from the repository root. The first search includes tracked tests and vendored code. The second also catches older-style declarations and exports whose signatures lack the Rust keyword. Inspect cfg gates, comments, macro expansions and the matching native implementation before classifying a hit.

```sh
git grep -n -w unsafe -- '*.rs'
git grep -nE 'extern "(C|system)"|no_mangle|mobile_entry_point' -- '*.rs'
git ls-files -- '*.c' '*.cc' '*.cpp' '*.h' '*.hpp' '*.m' '*.mm' '*.swift' '*.kt' '*.java'
git grep -nE 'unsafeBitCast|[Uu]nsafe(Pointer|Mutable|Raw|Bytes|Buffer)|assumingMemoryBound|withMemoryRebound|objc_(get|set)AssociatedObject|@_cdecl' -- '*.swift'
git status --short --untracked-files=all
cargo tree --manifest-path src-tauri/Cargo.toml --locked --target aarch64-apple-darwin -e normal,features
```

Repeat the last command for the packaged target and feature selection, and for `kiwix-mcp/Cargo.toml` on desktop. Consult [the app manifest](../src-tauri/Cargo.toml), [native build script](../src-tauri/build.rs), [mobile plugin](../src-tauri/plugins/tauri-plugin-kiwix-mobile), and [packaging guide](PACKAGING.md) for non-Cargo inputs.

To close a box, record the implementation commit, targets and features, what native or unsafe code remains reachable, comparison results and independent review. For platform-owned boundaries, record the isolation/lifetime guarantee and the exercised failure case. For the historical November 17 baseline, the locked app dependency graphs were inspected for ARM64 macOS, iOS and Android, ARMv7 Android, and x86-64 Linux and Windows. Each included AWS-LC, ring, bundled SQLite bindings, sherpa-onnx bindings and the Rust bzip2 backend on at least one normal dependency path. The ARM64 Apple and Android graphs also include `sha2-asm`. This baseline is source-traced. It includes no new device tests, sanitizer results or binary-level certification.
